## 3. tools.py 원본 vs 주석 없는 사본 (맡기기 7~8단계)

| 비교 항목 | 원본 (주석 있음) | 사본 (주석 없음) |
|---|---|---|
| 받는 값의 형식 | date: 문자열, "YYYYMMDD" 8자리 / title: 문자열, movieNm과 정확히 같아야 함 | date: str(추정), "형식은 파일에 적혀 있지 않다"면서 KOBIS 기준 "YYYYMMDD"일 것으로 보인다고 함 / title: str, movieNm과 완전히 같아야 함 |
| 예시 값 | date "20261031", 돌려주는 값 "123,456명" | date "20261031", 돌려주는 값 "123,456명" (원본과 같음) |
| 돌려주는 것 | 항상 문자열. 찾으면 "123,456명", 못 찾으면 "'파묘' 은(는) 20261031 순위에 없습니다." | 항상 문자열. 찾으면 "123,456명", 못 찾으면 "'영화제목' 은(는) 20261031 순위에 없습니다." |
| 틀리거나 애매한 부분 | docstring에는 "관객 수"라고만 되어 있는데 실제로는 일일 관객 수(audiCnt)라고 짚어 줌. 숫자와 안내문이 둘 다 문자열이라 구분이 어렵다고 함 | 틀린 곳은 없음. 대신 타입을 "코드로 추정"이라고 표시하고, 날짜 형식도 "~일 것으로 보인다"로 확신 없이 말함 |

- 7단계에서 읽은 파일: tools.py 하나 (Glob → Read)
- 원본 docstring에는 날짜 형식이 적혀 있지 않은데, 8자리 형식은 코드의 targetDt를 보고 추론함
- 8단계에서 tools.py 원본을 열어 봤는가: 안 열어 봄. Read 는 tools_nodoc.py 한 번뿐
- 정리: 원본 docstring 이 한 줄뿐이라 두 설명의 차이가 크지 않았음. 함수 이름과 코드가 분명해서 주석 없이도 거의 같은 설명이 나옴. 다만 주석이 없으니 "추정"이라는 표현이 늘어남

## 4. README.md 에서 사실과 다른 곳 (맡기기 9~11단계)

- 세 항목(무엇을 / 무엇을 설치 / 어떻게 실행)이 다 있는가: 세 항목 모두 있음. 27줄로 짧게 씀
- 권한 요청: Write — week09/README.md 새 파일. 요청한 일, 작업 폴더 안, 새 파일이라 지우면 됨 → 수락
- 확인한 것:
  - 없는 함수를 적었나 → 아님. get_movie_audience 는 tools.py 에 있음
  - 설치할 것 → requirements.txt 와 같음
  - 키 준비 → 들어 있음. tools.py 가 KOBIS_API_KEY 환경변수를 읽는 것과 맞음
  - 해 본 적 없는 결과를 적었나 → 아님. 출력 결과는 적지 않았고, main.py 를 실행해 보지 않았다고 대화에서 밝힘
- 사실과 다른 곳:
  - "영화 세 편을 조회" — main.py 의 세 번째는 "없는영화"로, 실제 영화가 아니라 순위에 없을 때를 시험하는 값임. 실제 영화는 두 편
- 그 밖에: README 를 쓰기 전에 요청하지 않은 observation.md 까지 읽었음 (폴더 안이라 묻지 않고 읽음)
